# Смена — работа, услуги и аренда персонала

Веб-приложение на Python / Django с русским интерфейсом, серверными HTML-шаблонами и адаптивным CSS. Основная база данных — PostgreSQL; для локального знакомства и тестов предусмотрена SQLite.

## Запуск с PostgreSQL

Требуется Python 3.12+, PostgreSQL 16 (или Docker Compose).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
docker compose up -d db
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver
```

Откройте http://127.0.0.1:8000/, админка — http://127.0.0.1:8000/admin/.
При запуске без Docker укажите в `.env` параметры существующего PostgreSQL. Файл `.env` читается автоматически; переменные окружения имеют приоритет. Не публикуйте его в репозитории. Если порт 5432 занят, измените проброс в `compose.yaml` и `POSTGRES_PORT` в `.env`.

## Быстрый запуск без PostgreSQL

После установки зависимостей:

```bash
DB_ENGINE=sqlite python manage.py migrate
DB_ENGINE=sqlite python manage.py seed_demo
DB_ENGINE=sqlite python manage.py runserver
```

Либо укажите `DB_ENGINE=sqlite` в `.env`. SQLite предназначена для локальной работы: блокировки строк, используемые при подтверждении аренды, полноценно работают в PostgreSQL.

## Демонстрационные аккаунты

Команда `seed_demo` создаёт данные повторно без дублирования существующих публикаций. Пароли существующих пользователей не меняются.

| Email | Роль |
| --- | --- |
| company@example.com | Работодатель, кофейня |
| partner@example.com | Работодатель, партнёрская компания |
| worker@example.com | Соискатель и исполнитель |
| design@example.com | Соискатель и дизайнер |

Пароль новых демонстрационных аккаунтов: `DemoStaff2026!`. Эти аккаунты предназначены только для локальной демонстрации; не создавайте их в публичной рабочей базе.

## Возможности

**Работодатель:** профиль компании, создание/просмотр/изменение/удаление вакансий, просмотр откликов и резюме кандидатов, изменение статуса отклика, поиск по базе резюме, прямые приглашения с контактами компании. Заказ услуг на выбранную дату; один отзыв с оценкой 1–5 после выполнения заказа. Создание и изменение предложений персонала, каталог предложений других компаний, исходящие и входящие заявки на аренду, подтверждение и отклонение заявок.

**Соискатель:** регистрация и вход по email, резюме с навыками, опытом и контактами, портфолио в виде ссылок и описания материалов, каталог вакансий с поиском и фильтрами по типу и зарплате, отклики и их статусы, входящие приглашения. Создание/изменение/удаление своих услуг, подтверждение входящего заказа, переходы «Подтверждён → В работе → Выполнен», просмотр отзывов и среднего рейтинга каждой услуги. Месячный календарь занятости с подтверждёнными заказами и ручной отметкой готовности; повторная запись на дату обновляет существующую.

**Общее:** публичные каталоги вакансий и услуг, страницы деталей, пагинация, CSRF-защита форм, разграничение прав на сервере, Django Admin для всех сущностей. Изменения выполняются через POST. Контакты и полные резюме доступны работодателям. Один соискатель может откликнуться на вакансию только один раз. Заказы сохраняют связь с услугой: услугу с заказами удалить нельзя.

При аренде проверяются количество, порядок дат и попадание в период предложения. Подтверждение блокирует строку предложения в транзакции и проверяет занятый персонал по пересекающимся заявкам. Проверка консервативна: суммируются все подтверждённые заявки, пересекающие запрошенный период. Количество и период предложения с подтверждёнными заявками менять нельзя. Публикации не являются оплатой, трудовым договором или расчётом заработной платы; платёжная интеграция не реализована.

Файлы портфолио не загружаются на сервер: используются описания и внешние ссылки. Доступность в календаре носит информационный характер и не блокирует отправку нового заказа; исполнитель подтверждает его вручную. Письма и уведомления во внешние сервисы не отправляются — все статусы и приглашения находятся в личном кабинете.

## Проверки

```bash
DB_ENGINE=sqlite python manage.py check
DB_ENGINE=sqlite python manage.py test
DB_ENGINE=sqlite python manage.py makemigrations --check --dry-run
```

Для проверки на PostgreSQL выполните те же команды без `DB_ENGINE=sqlite`; пользователь базы должен иметь право создавать тестовую БД.

Покрыты регистрация и вход, страницы и шаблоны, поиск и фильтры, ограничения ролей и владельцев, повторные отклики, приглашения, жизненный цикл заказа, авторство и уникальность отзывов, прошлые даты, сроки и лимиты аренды, изменение календаря и CSRF.

В среде разработки этой задачи тесты выполнены с локально доступным Django 4.2.1 и SQLite. Установка Django 5.2 из `requirements.txt` была недоступна из-за сетевых ограничений; проверка на целевой версии Django и PostgreSQL требуется после установки зависимостей. Локальный HTTP-сервер в этой среде также запрещён, поэтому визуальная проверка браузером не выполнена.

## Структура

- `config/` — настройки, маршрутизация и WSGI.
- `marketplace/models.py` — пользователи, профили, вакансии, отклики, услуги, заказы, отзывы, календарь и аренда.
- `marketplace/forms.py` — формы и проверки данных.
- `marketplace/views.py` — серверные сценарии и контроль доступа.
- `marketplace/migrations/` — начальная миграция базы.
- `marketplace/tests.py` — интеграционные тесты.
- `templates/` и `static/style.css` — русскоязычный адаптивный интерфейс.
- `compose.yaml` — PostgreSQL с постоянным томом.

## Развёртывание

Установите уникальный `DJANGO_SECRET_KEY`, `DJANGO_DEBUG=0`, конкретные домены в `DJANGO_ALLOWED_HOSTS`, безопасные параметры БД. Выполните миграции и `python manage.py collectstatic`, настройте HTTPS, reverse proxy и раздачу `/static/` из `staticfiles/`. Пример запуска WSGI:

```bash
gunicorn config.wsgi:application --bind 127.0.0.1:8000
```

При `DEBUG=0` включаются Secure-cookie для сессии и CSRF. Запускайте `python manage.py check --deploy` и настройте параметры прокси/HSTS под свою инфраструктуру. Для шрифта используется Google Fonts; без внешней сети интерфейс использует системный Arial.
